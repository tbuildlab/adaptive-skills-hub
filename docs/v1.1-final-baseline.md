## Duplicate-resolution policy

Discovery reads frontmatter metadata only (maximum 16 KiB) and records a metadata
fingerprint, provenance, and deterministic resolution. It does not read a whole
`SKILL.md` solely to break a duplicate tie.

Priority is: explicitly maintained local checkout, project-specific source,
user-level Codex Skill, other local source. Disabled paths are ineligible. A
higher tier wins; equal-tier candidates fail closed as `duplicate_conflict` until
a deliberate full-content audit establishes a safe authority decision.

- `python scripts/final_smoke.py`: 10/10 passed against the real 34-record index.
- The smoke suite fully loaded selected Skill instructions without authorizing any

  backend/testing chain, security, research architecture, research-to-document

- `MANIFEST.json` is regenerated after this baseline and provides static package
  integrity checking; runtime `state/`, generated `output/`, and `registry.json`
  are intentionally local-only because they contain volatile scans or large
  machine-specific live-test evidence.

## Deliberate limitations

- Discovery does not execute arbitrary prose in a Skill; Codex applies loaded
  instructions, and command hooks remain opt-in.
- Equal-authority duplicate copies are rejected rather than guessed.
- Registered upstream repositories and Agent definitions are distinct from
  executable installed Skills; candidate status is not a claim of use.
- The Hub directory is not a Git worktree, so no commit or tag was created.

No V1.2 behavior is introduced by this baseline.
