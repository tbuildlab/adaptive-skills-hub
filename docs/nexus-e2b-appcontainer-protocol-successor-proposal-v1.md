## 3. Exact local and provider gates retained in the successor

**Local gate:** the architecture proposal's Section 7 is conjunctive. The first variant runs with an empty capability set, no credential, no E2B SDK/API call, no Sandbox and no untrusted payload. A package SID or child status alone cannot pass. The exact executable/dependency bytes, environment, work/TEMP path, handle list, Job/deadline and independent observation channel must be fixed before the separately authorized test. If denial, loaded-byte identity, effective environment/handles, ancestry, controller-failure cleanup or owner-controlled attribution is ambiguous, classify `UNKNOWN` and stop.

**Networked variant gate:** `internetClient` or another network capability, if needed for envd, is a separate exact reviewed change to the LPAC capability set. Before provider G0 create, G1 review/token handoff or real E2B use of that variant, obtain separate owner authorization and complete a secret-free local isolation qualification using its actual executable/dependency byte identities, AppContainer/LPAC identity, capability set and launch configuration; repeat the independent secret, effective environment/handle, Job/descendant, deadline and cleanup checks. Missing or contradictory evidence is STOP. The capability enables broad Internet access, not an envd-only OS egress policy or exact-host allowlist. The local client must remain a pinned trusted fixed-operation implementation, and the complete Host/tool path must not let untrusted input choose arbitrary network operations. If an exact-host local egress restriction is mandatory but no independently enforceable layer exists, reject this mode; do not quietly add a proxy, firewall service, or capability. The later E2B guest's outbound restrictions remain subject to the original same-ID provider verification and effective-policy evidence limits.

**E2B G0/G1 gate:** after separate acceptance and authorization, perform fresh account/project/billing/remaining-RM5 checks, one exact request and same-ID observations, enumerate mutating actors, cleanly separate the owner control credential from the LPAC process, and reconcile cleanup/usage. The first untrusted guest command still needs a distinct owner G1 release after negative control-plane authority and positive envd-only tests. Any provider accounting lag is `UNKNOWN`, not zero. Neither local LPAC PASS nor a proposed successor protocol is E2B qualification, `ITEM_B PASS`, G2 Host qualification or G2 acceptance.
