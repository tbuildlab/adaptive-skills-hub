subset, fixed source-derived retention worker, 1,050-byte task, three source
hashes, local-only hard policy, `model_ref=null`, strict CSV acceptance, resource
bounds, local routing and physical guard. No candidate/model runs or new private
corpus is involved. Six new exact subjects are required; all old decisions remain
consumed and every old attempt remains unchanged and permanently retired.

The shared experimental guard supplies exact-subject authorization, confinement,
Job/collector/lifecycle safety and protocol validation in BOTH arms. None of that
may be attributed to incremental Nexus benefit. Likewise, independent observer
hashes, experiment metadata, this pilot's fairness harness and common file/hash/
exclusive-write/readback services are not a Nexus-only achievement.

Native arm: the Host runs the exact worker; an explicit native stdlib recipe
derives the expected CSV independently from the same input, checks the full
protocol, writes the artifact exclusively, reopens/hashes it, and returns the
same factual receipt and interrupted-result inspection capability. It does not
call the Nexus verifier or full Nexus wrapper. Equivalent task instructions,
validation, receipts, native features and recovery inspection are retained.

Nexus arm: the identical action uses the existing source-derived Nexus verifier
and its usual artifact/readback bookkeeping. It does not get looser acceptance
or extra execution permissions. Factual rubric items are identical; JSON names,
receipt aesthetics, shared containment and framework presence are not benefits.

In particular, all metadata facts produced by common `_finish` services receive
zero incremental credit in BOTH arms. The common seven-fact checklist measures
completeness and loss, but its common implementation cannot create a Nexus win.
This negative control may have no discriminating benefit at all. Do not promote
it to affirmative governance value or broaden its task to obtain an advantage.
Validator-equivalence claims concern this fixed input and tested PUBLIC fixtures,
not arbitrary task corpora. The native recipe retains the fixed worker's 16-byte

Only the closed slot/configuration and the post-output validation recipe differ.
No Core hook, Git-only Host loop, existing milestone or production adapter changes.

## Population, fixed order and intervention

Population: one already-qualified PUBLIC retention-index task under local-only
routing, including its explicitly injected artifact-finalization failure case.
It cannot establish general model quality, confidential-data handling or value
across other tasks. Previous qualification outputs are not pilot observations.

The exact order is native_1, nexus_1, nexus_2, native_2, native_interrupted,
nexus_interrupted. Thus two normal pairs reverse order; one pair applies the
same deliberate failure after validated worker output, before artifact commit.
This is a finalization interruption, not an OS/controller crash claim. The
interrupted requested artifact remains uncompleted; original local output is
retained for inspection, without redispatch or authority restoration.

Maximum: six fresh slots, each with a different signed subject and exclusive
directory, one execution per subject. There is no retry or replacement slot.
Each retains existing 180-second guarded wall, 120-second user CPU, 2-GiB Job
memory, eight processes and 65,536 combined output bytes. Existing bounded guard
cleanup remains unchanged. No tighter aggregate timing guarantee is invented.

Verification-only for all six signatures must complete before batch reservation.
Any unexpected failure stops the batch; all unused slots receive retired,
not-dispatched dispositions, so neither the batch nor unused signatures can be
replayed. Every terminal outcome retires all six slot opportunities. Planned
interruption outcomes are retained as unsuccessful artifact completion, never PASS.
No background dispatch, scheduling, replanning, reset or automatic recovery exists.

## Measurements fixed before pilot dispatch

Measure policy violations, evidence completeness, recovery accuracy, acceptance,
retries, cost, latency, human intervention and failure transparency. Scope each
measurement to observable facts; unavailable measurements remain UNKNOWN.

Evidence-completeness rubric: seven factual items, equally available in both arms:
input identity, source identities, original output identity, artifact commit/
readback identity or explicit no-commit outcome, exact-subject provenance link,
terminal disposition/no-redispatch status, and truthful uncertainty/recovery
disposition. Count each fact once; shared observer facts do not add arm credit.
The primary outcome is incremental arm-produced evidence completeness. Minimum
worthwhile benefit is one additional inspectable fact out of seven without
worse policy/acceptance/recovery behavior. A tie is not benefit.

Normal acceptance is exact source-derived CSV plus exclusive artifact/readback.
Interrupted acceptance is zero completed artifacts and explicit retained unknown/
partial disposition. Recovery accuracy requires correctly distinguishing original
valid output from unsettled artifact completion and retaining it without retry.
Failure transparency concerns truthful outcome and evidence availability, not
Nexus-specific schema fields. Policy-violation counts cover observed fixed routing,
source/output identities, state and bounds only; do not claim unobserved universal
absence. Retries and human interventions are explicit counts, not assumed savings.

End-to-end time includes current per-slot eligibility, guard and finalization.
Also retain guard and finalization timings separately. The common batch-wide
verification-only phase and one Owner signing action per slot are disclosed,
not attributed to either arm as a difference. Task-specific tolerated overhead
for considering a later comparison: no more than 20% plus 250 ms of the paired
native end-to-end latency, with no extra human intervention. Two normal pilot
pairs only estimate a range; they do not support statistical superiority.

No new paid/cloud/provider resource is allowed. Actual local energy/hardware
monetary cost remains UNMEASURED, not zero or monetary savings. Provider-facing
budget uncertainty or any new payment requirement stops before dispatch. The
future final value protocol must retain missing cost as UNKNOWN and obey its
existing unknown-cost STOP rule; this pilot cannot silently relax that contract.

Keep all failed/interrupted/partial observations. Do not choose another comparator,
