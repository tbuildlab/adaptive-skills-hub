## 3. Accepted order and removed guarantees

One protected enforcement domain owns the original sequence and sole eligible
consumer/capability. CLOSED/REVOKED/EXPIRED and COMMIT_L compete in that same
protected order. Closure first forbids a new commit and eligible invocation.
Commit first allows at most that original fixed synthetic operation, including
possible later native call entry or completion. Later closure is still recorded,
closes all other admissions and cannot erase the winning original decision.

External Owner request, domain receipt, logical revocation/expiry transition,
admission, intent persistence, logical commit, physical submission/mutation,
completion and cessation remain separate evidence facts. Effective closure
acknowledgement requires the exact protected order and required persistence;
neither acknowledgement nor COMMIT_L proves no prior effect or settled cessation.

Expiry processing is domain-local. A prior valid sample followed by delay may
precede a logical commit after external expiry but before EXPIRE_L. Never claim
that external expiry instantly prohibits new commitments, that physical effect
cannot occur after expiry, or that a clock reading backdates a later event.
The accepted property is no new logical commit AFTER protected ordered closure.

The removed guarantees are external-time commit/effect cutoff and instantaneous
stop of previously committed residue. Their absence is explicitly accepted for
this harmless synthetic scope; it is not a compatible implementation of old SD05.
No mutex, timer, memory atomic, flush or marker hash is promoted to a clock/file
transaction or finite all-fault termination fence.

or uncertain original cannot be reconstructed as UNUSED. Reconciliation and
cleanup need their own valid scopes and authentic original observations.
