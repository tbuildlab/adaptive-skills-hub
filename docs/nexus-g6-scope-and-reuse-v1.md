The Roadmap's historical G1 NOT STARTED banner is the original freeze status,
not an override of later implementation. Old generic Agent/Web OS roadmap ideas
were superseded by V2 allocation; they are not merged into G6. G5 is optional in
the Roadmap, A5 and G2 v3. Disabled delegation remains an explicit tested support
restriction. No parallel product executor or G5 platform is implemented.

Roadmap F requires all A-H scenarios. A6 additionally requires deferred/indirect
admission, transitive delegation, configuration drift, observation gaps, compaction
loss, revoked resume, cancellation/late effects, unknown/revised cost and whole-path
privacy. Refusal-only results cannot satisfy useful workflow/substitution success.
Capability completion and governance correctness remain distinct. G6 cannot
replace unqualified local/private execution with a documented refusal.

Value thresholds/materiality are task-specific and must be locked after a separate
pilot, before comparison. The readiness matrix W28 records the missing rubric;
no universal percentage or savings is invented here. A draft protocol with unknown
thresholds is valid preparation, not a preregistered experiment or measured benefit.
The native comparator keeps equivalent inputs, permissions, criteria and relevant
native features. G5 Arm C is omitted in this sequential scope.

## New deterministic gap justification

```text
WHY_EXISTING_NEXUS_INSUFFICIENT = existing validators, packages and domain records do
  not encode G6 support/coverage, fair preregistration, split results, release/freeze evidence
WHY_OPENAI_HOST_INSUFFICIENT = an executor cannot independently self-assert exact
  artifact/configuration binding, required coverage, conserved restrictions or qualification
WHY_NEW_CODE_REQUIRED = reject malformed/incomplete/substituted evidence and misleading
  PASS promotion with deterministic closed contracts; preserve non-authority in integration
MINIMAL_SCOPE = pure g6_contracts; thin g6_host_adapter; static preparation inventory;
  tests and versioned documents; no I/O, dispatcher, lifecycle service or generic benchmark engine
```

Per-module gap justification:

| Module | WHY_EXISTING_NEXUS_INSUFFICIENT | WHY_OPENAI_HOST_INSUFFICIENT | WHY_NEW_CODE_REQUIRED | MINIMAL_SCOPE |

| g6_contracts | Existing G1/G4 validators do not express the five accepted G6 records or cross-record coverage/fairness/freeze constraints | Executor claims cannot establish conserved policy, exact evidence links or split qualification | Enforce bounded closed records and reject mismatched, missing, stale, substituted or misleading evidence | Pure data validation and hashing; no authentication, execution or experiment engine |
| g6_host_adapter | G4 checks domain evidence and admission, but does not compose G6 release identity with those domain checks | The Host must not promote its own structural report into publication authority | Bind the existing G4 and new G6 checks to one task/artifact and preserve production DENY | Small composition functions; reuse G4 typed gate; no new transport, recovery engine or grant |

No existing G4/Core/G1/G2/G3 production behavior is redesigned. New qualification
records remain untrusted evidence, including when hashes and structural checks pass.
No fixtures, history, Git commit, scanner result or model assertion creates a grant.
G3 INCOMPLETE, D01 CLOSED, D03 DEFERRED, REAL_ADMISSION NO are not configurable here.
Historical D04 status stays unchanged; delegated-mode executor exclusion is not
reintroduced as a release gate. Independent complete-mediation coverage belongs
to the actual scenario/support requirement, not a relabelled D04 blocker.

## Finite preparation completion and freeze boundary

Complete contracts, thin deny-only integration, coverage preparation, meaningful
negative tests, full Python/Node regression, source/package hygiene, docs/MANIFEST,
commit/push and remote-ref verification. Test only observable evidence and contracts,
never hidden model reasoning. Retain failed/interrupted/unsupported outcomes.

Production Security Freeze still requires the actual Roadmap sequence: defensive
review/fixes/retest, independent review, full regression, exact artifact approval,
qualified publication path and owner acceptance. No final production tag is created
from this preparation checkpoint. Live gaps are recorded separately while all
independent preparation proceeds; no routine human interruption is required.
