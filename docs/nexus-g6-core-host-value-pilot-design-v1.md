# G6 retained Core Git workflow value pilot

Status: PROSPECTIVE PILOT DESIGN; no observations at registration. This is not
the completed retention-index experiment, a final comparison, or G6 acceptance.
The retention pilot's task, comparator, thresholds, metrics, results and six spent
authorizations remain unchanged. Its redundant transform responsibility stays
delegated to native Host use.

## Responsibility and finite population

Evaluate the existing post-G2 Core Git Host workflow's scope/checkpoint/verified
completion responsibility. Do not reopen G2, G3 or G4. Use only existing trusted,
non-secret local Python/Git facilities and current explicit task/Host authority.
Ordinary read-only Core Host tasks require no new component signing ceremony;
this is not candidate adoption, capability registration or private execution.
The previous native-role signatures confer no authority here and are not used.

Fixed task: inspect Git metadata and whitespace for `README.md` and
`docs/nexus-roadmap-v2.md`, and return a verified maintenance report outside the
inspected repository. Three cases inspect the actual Nexus checkout. A fourth
uses a separately materialized PUBLIC copy of those two project files, with one
preexisting controlled trailing-whitespace finding. Setup creates that disposable
input repository before observations; task execution never edits either input
repository. There is no stage/commit/push/reset/clean/deploy/remote action during
an inspected task. No confidential input, model/provider invocation or new runtime.

Four cases, one observation per arm per case:

1. `clean`: actual tracked repository inspection and exact report readback.
2. `findings`: identical inspection of a PUBLIC input snapshot with a truthful
   existing whitespace finding; expected `completed_with_findings`.
3. `resume`: actual inspection, pause after two completed observations, then
   continue in a fresh Python process without repeated completed actions or a
   renewed budget/deadline. Expected verified completion.
4. `pending_unknown`: perform actual inspect reads, deliberately withhold their
   acknowledgement, then settle as ambiguous without redispatch or a report.
   This is an observation-loss injection after reads, not OS crash proof or
   successful requested artifact delivery.

Locked order: clean native/Nexus; findings Nexus/native; resume native/Nexus;
pending_unknown Nexus/native. Exactly eight fresh slot directories, no retries
or replacements. An unexpected failure stops and retires remaining slots.

## Fair native comparator

Both arms have the same logical task, exact input bytes/worktree per pair,
Git executable/arrays, local Python Host, file/hash tools, strict Git exit-code
handling, scope hashes, checksum-bound checkpoint files, budget/deadline,
fresh-process continuation, fresh repository comparison, exclusive report write,
report reopening and truthful unknown/no-replay instructions. The native arm is
a fixed stdlib/Git Host recipe; it does not call Nexus planning, verifier, state
or execution APIs. The Nexus arm uses existing `core_host_loop` prepare/next/
observe and checkpoint helpers. Shared Git observation/trace services receive no
incremental evidence credit. A different JSON schema or extra receipt fields is
not a benefit. No new generic agent, process-control or execution framework.

This is a finite deterministic Host-recipe comparison, not a benchmark of model
reasoning, conversational compaction or general autonomous coding. The trusted
local Host scope supplies no new sandbox or universal network/privacy claim.
Git commands disable optional locks, pager, fsmonitor, untracked-cache mutation,
external diff and textconv as applicable. Dangerous actions remain outside this
profile and subject to the existing Host boundary.

## Prospective measurements and stopping rules

Primary: count correctly verified completion/safe disposition, from zero to four
per arm, against independent current repository and checkpoint facts. Normal
completion must actually reopen the report and match fresh state. A false clean
claim, stale completion, reset budget, blind redispatch or refusal on a supported
unchanged normal task is incorrect. Ambiguous pending work must remain incomplete.
Minimum worthwhile benefit: one additional correct case out of four without a
worse policy violation, artifact acceptance or recovery result. A tie is no
incremental benefit. The result is not assumed favorable to Nexus.

Also retain all nine Roadmap metrics: policy violations, evidence completeness,
recovery accuracy, acceptance, retries, cost, latency, human intervention and
failure transparency. Common observer facts earn zero incremental credit.
Tolerable paired latency overhead is 20% plus 250 ms; no extra runtime human
intervention is permitted. Per-task bounds remain eight logical Host batches,
600 seconds overall and 20 seconds per action. The resume continuation preserves
the original values. Parent actor timeout is 180 seconds, with stop/quarantine
on uncertainty; it is not evidence of OS process-tree containment. Only PUBLIC
trusted read actions run; no descendant sandbox guarantee is invented.

This pilot estimates variability. It does not preregister a final comparison or
select a repetition count retrospectively. A final evaluation, if justified,
needs a separate locked protocol before new observations. Do not change the
comparator/task/thresholds after seeing results, or continue task hunting for a win.

## Dated monetary estimate, not total economic cost

Date: 2026-10-16. Prospective scope is **incremental attempt billing**, in USD
microunits, covering execution, retries, validation, task-specific local context
preparation, tools/infrastructure and expected human recovery inside each fixed
attempt. All six are estimated zero additional charges only for the declared
existing local, non-billable operations: no provider/API/cloud process, no new
subscription/resource, no license-per-invocation operation, no retry or paid
human recovery. Task-specific source/authority preflight and local setup are
included, not hidden as free Nexus work. Common study preparation/conversation
and immutable input-material setup are excluded symmetrically and disclosed.

The installed Python/Git tools are existing facilities. Primary license sources
support royalty-free/free software use; the exact executable hashes and actual
operation inventory must additionally be retained. Licenses alone do not prove
that no charged service was called. The closed reviewed local recipe and traces
must establish the attempted operations. Any unpriced/provider/billable/human
operation makes the affected cost UNKNOWN and stops further dispatch. Unknown
cost remains STOP, never zero. Human assistance being disallowed means quarantine
when assistance becomes necessary, not successful free recovery.
