# Nexus Desktop Plugin and portable-distribution pilot

This pilot adds a **private local integration layer** over the frozen Nexus
V1.2 Core and accepted Runtime R1/R2/R3 work. It does not change routing,
planning, skill selection, the R2 tool surface, or any frozen tag.

## Architecture

`plugins/nexus-desktop` is a local Plugin with a user-facing display name of
**Nexus**. Its bundled `nexus` Skill tells a supported host to call the existing
read/plan-only R2 tool `nexus.plan_task` for substantive work only. Its bundled
MCP mapping starts a standard-library launcher from the installed Plugin root.
That launcher reads the private, user-owned local configuration generated by
`scripts/setup_nexus.py`, validates it, and starts the existing
`scripts/nexus_mcp.py` entry point with a fixed argv list and `shell=False`.

The bridge has no network endpoint, OAuth, GUI, automatic installation, shell
execution, arbitrary caller-path input, or independent planner. R2 continues to
enforce opaque workspace IDs, safe context bounds, redaction, and native fallback.

The Plugin’s MCP mapping is intentionally separate from the older standalone
`nexus-r2-local` registration. Do not enable both servers in one host session:
the tool names overlap. Keep the standalone registration unchanged as the R3
rollback path; for Plugin acceptance, disable/remove it temporarily and restore
it afterward with the accepted R3 command.

## Private install

From a cloned Nexus checkout, use the primary setup command. It creates only a
Nexus-owned local data directory (normally `%LOCALAPPDATA%\Nexus`) and preserves
backup copies before replacing Nexus-owned JSON files:

```powershell
python scripts/setup_nexus.py install `
  --workspace-root D:\work\my-project
```

By default it creates a local Python environment and installs only
`requirements-r2-mcp.txt`. To use an already provisioned R2 runtime, pass its
absolute Python executable explicitly:

```powershell
python scripts/setup_nexus.py install `
  --workspace-root D:\work\my-project `
  --runtime-python D:\path\to\python.exe
```

The installer fails closed if a standalone `nexus-r2-local` registration already
exists, preventing duplicate tool registrations. After keeping that trusted
configuration for rollback, temporarily remove/disable the standalone server and
ask the official Codex CLI to configure the local marketplace and install the
Plugin:

```powershell
python scripts/setup_nexus.py install `
  --workspace-root D:\work\my-project `
  --with-plugin
```

The setup script never parses, edits, or overwrites `~/.codex/config.toml`.
`--with-plugin` delegates only Plugin lifecycle changes to `codex plugin`.
The Plugin uses the fixed opaque alias `nexus-default`; setup maps it to the
single approved `--workspace-root` without putting a filesystem path in the
bundled Skill.

## Verify, update, remove, and rollback

```powershell
python scripts/setup_nexus.py check
codex plugin list
```

For an updated private checkout, reinstall only after validating the new source:

```powershell
python C:\Users\<user>\.codex\skills\.system\plugin-creator\scripts\update_plugin_cachebuster.py plugins\nexus-desktop
codex plugin add nexus-desktop@nexus-local-pilot
```

Start a new Desktop conversation after installation or update.

Remove the Plugin and its local marketplace, then remove only Nexus-owned local
configuration (backups are retained):

```powershell
python scripts/setup_nexus.py uninstall --remove-plugin
```

To return to the accepted standalone R3 integration, remove/disable the Plugin,
then restore the existing standalone command with your previous trusted runtime
and workspace configuration:

```powershell
codex mcp add nexus-r2-local -- <python.exe> <nexus-root>\scripts\nexus_mcp.py --workspace-config <workspaces.json>
```

No source checkout, Core behavior, or frozen tag changes during removal.

## Human Desktop acceptance checkpoint

Automated validation cannot prove a UI mention surface. In a **new ChatGPT
Desktop conversation**, open Plugins, enable `Nexus`, and run exactly:

1. `@Nexus Create an editable PowerPoint presentation about digital transformation in business.`
2. `@Nexus Diagnose an API HTTP 500 and add a regression-test plan.`
3. `@Nexus What is 2 + 2?` — expect the Skill to bypass the planner for a trivial task.
4. Disable/remove the Plugin, restore `nexus-r2-local`, restart Desktop, and
   repeat `Use Nexus to plan an editable PowerPoint presentation.`

Record whether the actual UI offers `@Nexus`, whether the Skills are loaded, the
tool call is visible, the PowerPoint plan selects a real presentation capability,
and the standalone R3 rollback still works. Do not call this UI acceptance passed
until a human observes it.

## Distribution boundary

This is a private pilot, not a public release. The source archive contains only
Nexus-owned source, Plugin metadata, the thin launcher, tests, and documentation.
It excludes local workspace configuration, logs, state, output, caches, private
Skills, credentials, personal paths, and virtual environments. There is no public
license grant in this pilot; the manifest correctly identifies it as Proprietary.
