## 5. Planning, tools, orchestration and protocols

Planner versus executor and agent versus tool are useful semantic distinctions, already materially covered. S07 turns a typed plan into a concierge prompt; dependency ordering in text is not a deterministic enforced execution graph. S04 describes schemas and approval modes but its booking function returns a confirmation string; that is not real booking evidence. S08's budget reviewer is an LLM review of a travel budget, not a spending guard. Names, docstrings, Agent Cards and discovered tool schemas can identify a candidate; they do not prove invocation, permission or trust. Preserve N1's minimal role/dependency selection and N3's independent eligibility gates.

M08 distinguishes centralized/decentralized/hybrid coordination. G5 already defers qualified bounded child work: authority attenuation, aggregate resource ownership, bounded depth and complete reachable effect paths remain necessary. Passing a chat context or linking executors does not prove them. Recursive delegation, termination and failed-agent effects cannot be inferred safe from sequential event streaming. Do not add a DAG scheduler, group-chat runtime or universal agent envelope to represent a simple governed step.

M11 distinguishes MCP tools/resources/prompts, A2A cards/tasks/artifacts and NLWeb query/retrieval services. S11M explicitly **simulates** MCP discovery with local functions; S11A explicitly uses an **in-process** workflow to simulate A2A-style cooperation. Neither notebook establishes real transport conformance, authentication, isolation or remote-effect semantics. The course's claims about protocol authentication do not establish Nexus invocation authority. R2 already supports a scoped local MCP planning interface; it is not missing MCP in general. Remote MCP, A2A and NLWeb implementation would be separate future integration, without evidence here requiring it now. Discovery, resource access, transport identity, invocation authority and result provenance should remain distinguishable through existing references, not through mandatory new adapters.
